# 飞书机器人从零开始操作指南

日期：2026-10-21。适用于当前 Medical NLP 项目。

> 后续进展：飞书接入代码现已实现并完成离线测试。你已完成第 1–5 步，请接着阅读 [接入程序实际配置与启动说明](../integrations/feishu/README.md)，使用其中的准确命令。下文第 6 步之前的“尚未实现”描述保留为最初操作顺序，实际 SDK 与飞书联调仍待验证。

这份文档按实际操作顺序写。每完成一步，再做下一步；遇到“先停在这里”，先解决该处的问题。

**你现在从第 1 步开始。第一次只需要做到第 5 步。**

当前情况：项目已经有医学文本分析功能，但还没有连接飞书的程序。仅在飞书后台创建机器人，它还不会调用项目。下面会明确告诉你什么时候操作飞书、什么时候让 Codex 编写程序。

我们先用当前 Windows 电脑跑通单聊和群聊，暂不购买服务器。第一版只处理现有的医学缩写扩写与概念映射，每次粘贴一段英文，不上传文件，也不连续追问。

> 页面名称按飞书常见后台编写，实际界面可能略有差异。若找不到对应项，记录步骤编号并提供不含密钥的页面截图，不要改成另一种机器人。本文没有读取你的飞书后台，因此下列完成状态需要你逐项检查。

## 第 1 步：打开飞书开发者后台

**由你操作，使用浏览器。**

1. 打开 [飞书开发者后台](https://open.feishu.cn/app)。
2. 用你平时的飞书账号登录；出现二维码时，用手机飞书扫码确认。
3. 如果出现组织选择，选你准备使用机器人的组织。后面测试时，飞书客户端也要使用这个组织身份。
4. 在应用列表中找到“创建企业自建应用”或含“自建应用”的创建入口。

**完成标志：**能看到创建自建应用的入口。

如果只看到申请权限、没有创建入口：先确认当前组织身份，再联系该组织管理员处理开发权限。不要先去群设置里创建 Webhook 自定义机器人，那不是本指南使用的入口。

## 第 2 步：创建一个应用

**由你操作，仍在开发者后台。**

1. 点击“创建企业自建应用”。
2. 应用名称填写：`医学文本标准化助手`。
3. 应用描述可以直接填写：

   > 接收英文临床文本，调用 Medical NLP 项目完成医学缩写扩写和标准概念映射，并返回处理结果。

4. 按界面要求设置图标。可以先使用后台允许的简单图标；如果要求上传，选一张你有权使用的图片。
5. 点击“创建”，进入刚创建的应用。

**完成标志：**应用详情页显示“医学文本标准化助手”，左边有应用配置菜单。

## 第 3 步：给应用添加机器人能力

**由你操作。**

1. 在左侧找“添加应用能力”或“应用能力”。
2. 找到“机器人”卡片，点击“添加”或“开启”。
3. 如果要求填写机器人名称，使用 `医学文本标准化助手`。
4. 如果要求填写介绍，使用第 2 步的描述。
5. 保存。

**完成标志：**应用中能进入“机器人”配置页，能力已添加或已启用。

这一步只是让应用具备聊天入口，暂时不会自动回复。

## 第 4 步：找到应用凭证，但先不用复制给任何人

**由你操作。**

1. 找到“凭证与基础信息”或同类菜单。
2. 确认能看到 `App ID` 和 `App Secret`。
3. 记住这个页面的位置。暂时保留浏览器标签页即可。

两者的作用：

| 名称 | 可以怎样理解 | 后续怎么用 |
|---|---|---|
| App ID | 应用编号 | 填进接入程序配置 |
| App Secret | 应用的连接密钥 | 只填进本机配置文件 |

**完成标志：**你知道在哪里找到这两个值。

不要将 App Secret 发到 Codex 聊天、截图或 GitHub。第 6 步会先让 Codex 创建配置模板，第 7 步再由你填写。

## 第 5 步：申请三类消息权限

**由你操作。**

1. 打开应用左侧“权限管理”。
2. 找“开通权限”“添加权限”或同类按钮。
3. 在搜索框中逐项搜索以下权限。优先核对权限代码及说明，不只看名字是否相似。

| 需要的能力 | 可搜索的权限代码 | 用途 |
|---|---|---|
| 读取用户发给机器人的单聊消息 | `im:message.p2p_msg:readonly` | 私聊时收到英文文本 |
| 接收群聊中 @ 机器人的消息 | `im:message.group_at_msg:readonly` | 群内被 @ 时收到英文文本 |
| 以应用身份发消息 | `im:message:send_as_bot` | 给用户返回结果 |

4. 选择应用身份权限，按后台提示申请或开通。
5. 记录每项实际显示的是“已开通”“待审批”还是其他状态。

**完成标志：**上述三类权限已经找到并申请；正式聊天测试前必须生效。

如果搜不到某个代码：搜索对应中文含义，查看“接收消息”事件或“回复消息”接口的权限要求。有历史权限或新名称时先核对，不要为省事全选所有权限，也不需要读取全部群消息。

**第一次操作先停在这里。接下来需要写连接程序；当前仓库还没有它。**

## 第 6 步：让 Codex 编写飞书接入程序

**你发送任务，Codex 完成代码工作。**

在当前项目的 Codex 聊天中发送下面这段话。它是一段开发任务，不是要复制到 PowerShell 的命令：

```text
我已完成《飞书机器人从零开始操作指南》第 1–5 步。
请开始实现飞书接入程序，支持单聊与群聊真正 @ 机器人后的英文纯文本输入。
使用企业自建应用和官方 Python SDK 长连接，调用现有 POST /expand/simple。
实现帮助消息、测试用户/群允许列表、去重、有界队列、后台分析、状态如实展示、超时及回复失败处理。
请创建本机配置模板、独立依赖环境说明，以及实际可运行的启动/停止方式。
先做不联网、不发送飞书消息、不调用付费模型的隔离测试。
完成后明确告诉我配置文件的绝对路径、我要填哪些字段、如何取得测试身份 ID，以及准确启动命令。
遵守项目改动日志要求；不要提交或推送 Git，不要自动启动连接或真实联调。
```

开发完成时，核对 Codex 是否交付了：

- [ ] 实际接入代码，而不只是另一份方案。
- [ ] 有明确绝对路径的配置文件模板。
- [ ] 依赖安装和启动命令，并说明在哪个终端执行。
- [ ] 无模型调用的“帮助”功能。
- [ ] 获取并设置测试用户、群及机器人身份的方法。
- [ ] 去重、错误状态和会话不串线的隔离测试结果。
- [ ] 停止方法和日志位置。

**完成标志：**代码已生成并通过隔离测试，但还没有连接飞书。

未达到这个标志，不要继续找“启动机器人”的命令。本指南不假造一个尚未实现的启动脚本。

## 第 7 步：把凭证填到本机配置文件

**由你操作，使用 Codex 第 6 步交付的配置文件。**

1. 打开 Codex 指定的配置文件；如果给的是 `.env.example`，按它交付的步骤复制成运行时配置，不覆盖已有配置。
2. 回到飞书“凭证与基础信息”页面。
3. 复制 App ID，粘贴到对应项，例如 `FEISHU_APP_ID`。
4. 查看并复制 App Secret，粘贴到对应项，例如 `FEISHU_APP_SECRET`。
5. 后端地址、允许用户/群等字段按实际开发交付说明填写，不猜 ID。
6. 保存文件。

配置看起来可能是下面这样，**这里只是格式示例，字段名称以实际交付为准**：

```dotenv
FEISHU_APP_ID=这里填写你的应用编号
FEISHU_APP_SECRET=这里填写你的应用密钥
MEDICAL_API_BASE_URL=http://127.0.0.1:8000
```

本地运行 API 也可能使用 8001，不能一律填 8000。第 11 步会确认真实地址。

**完成标志：**配置文件已保存，运行程序可以读取所需项。让 Codex 检查“是否存在、是否仍为占位符、是否被 Git 忽略”，不打印真实密钥。

## 第 8 步：启动连接程序，并配置消息事件

**你操作后台和终端，Codex 可根据实际输出协助。此步会连接飞书。**

1. 打开 Windows Terminal 或 PowerShell，进入项目：

   ```powershell
   Set-Location 'E:\Work\B_RAG\Try\medical-nlp'
   ```

2. 执行第 6 步交付的依赖安装命令；如果已安装则按交付说明检查即可。
3. 执行第 6 步交付的接入程序启动命令。先使用配置/连接检查模式；此时不用发送病例。
4. 保持终端开启，确认没有缺配置、密钥无效等错误。
5. 回到飞书后台，进入“事件与回调” → “事件配置”或同类页面。
6. 找到订阅方式，选择“使用长连接接收事件”。
7. 若后台提示需要先建立连接，确认步骤 3 的程序仍在运行，再保存。不要改选需要公网地址的方式。
8. 点击“添加事件”，搜索“接收消息”。
9. 添加事件代码 `im.message.receive_v1`，有的界面显示“接收消息 v2.0”。
10. 核对事件要求的权限与第 5 步一致，保存。

**完成标志：**订阅中有接收消息事件，长连接配置已保存，程序连接无报错。

若提示“应用未发布”：先做第 9 步发布已有配置，再返回本步建立连接、保存事件。订阅或权限变更后，按后台提示再次发布。不同账号配置顺序可能有差异，以当前错误提示为准。

如果需要取得测试用户和群 ID，使用第 6 步交付的明确身份登记方式。不要临时把允许列表清空来放行所有人；登记阶段只处理身份/帮助，不执行医学分析。

## 第 9 步：发布应用，只开放给测试人员

**由你操作飞书后台。**

1. 找到“版本管理与发布”。
2. 点击“创建版本”。
3. 第一次版本号可填写 `1.0.0`；如果已有版本，按后台规则使用新版本号。
4. 更新说明填写：`首次接入 Medical NLP，测试单聊与群聊 @ 消息处理。`
5. 按界面要求完善应用图标等必填信息。
6. 在可用范围中先选择你自己；如需他人测试，再加入明确的测试成员。
7. 保存并提交发布。账号可能直接发布，也可能需要组织管理员审批。
8. 等待状态变成“已发布”或后台等效状态。

**完成标志：**最新配置对应的版本已发布，测试人员在可用范围内。

“保存”“提交审批”都不等于发布完成。以后修改权限或事件时，也要查看是否提示重新发布。

## 第 10 步：先在单聊里测试“帮助”

**由你操作飞书客户端。**

1. 确保第 8 步的连接程序仍运行。
2. 打开飞书客户端，切换到创建应用的组织。
3. 搜索 `医学文本标准化助手`，进入机器人单聊。
4. 发送 `帮助`，具体命令以第 6 步实现为准。
5. 查看机器人是否回复使用说明。

**完成标志：**单聊能收到帮助消息，此测试不调用医学模型。

收不到回复时依次检查：

1. 应用是否已发布、你是否在可用范围内。
2. 单聊读取和发送权限是否生效。
3. 是否订阅接收消息事件。
4. 接入程序是否仍运行、是否成功连接。
5. 你的用户身份是否被允许。

如果连输入框都没有，优先检查机器人能力、接收消息事件与发布状态。先把帮助测试跑通，再查医学后端。

## 第 11 步：确认原来的 Medical NLP 网页能工作

**先检查，再决定是否需要启动已有服务。**

1. 在浏览器打开你原来使用的项目地址。如果使用仓库当前 Compose 默认端口，可以试 [本机网页 8000](http://127.0.0.1:8000/app)；如果是原有本机开发服务，可能是 [本机网页 8001](http://127.0.0.1:8001/app)。
2. 若网页可以打开，记下实际地址，但不要因此认为模型和数据库已经可用。
3. 如果打不开，先让 Codex 检查已有进程、端口和 Docker 容器。可以直接发送：

   ```text
   我进行到操作指南第 11 步。请只读检查当前 Medical NLP 服务、8000/8001 端口、Docker 容器与已有数据，告诉我应该使用哪个地址以及需要怎样启动。先不要新建或重建数据库，不要删除数据卷，也不要启动重复服务。
   ```

4. 根据检查结果启动原有服务，不要复制首次建库命令覆盖已有数据。
5. 网页正常后，在 Analyze 页面输入下面的虚构示例，点击“分析”：

   ```text
   The patient has SOB and CP.
   ```

6. 等待网页返回结果。这一步会执行项目实际流程，可能产生现有模型 API 调用费用。

**完成标志：**网页完成一次真实请求并显示扩写、映射或明确的业务状态，而非连接错误或后端异常。某项“暂不编码”不一定表示系统故障，应按实际状态判断。

如果网页报错，先修好原项目再继续；如果 `/health` 显示 ok，但 Analyze 失败，也不能跳过。该健康接口只检查 API 进程，不检查 Milvus 与模型。

## 第 12 步：把机器人指向刚才验证过的后端

**由你编辑配置，再重启接入程序。**

1. 回到第 7 步的配置文件。
2. 若机器人作为普通 Windows 进程运行，后端网页是 `http://127.0.0.1:8000/app`，则 API 基础地址填写 `http://127.0.0.1:8000`。
3. 如果网页使用 8001，就填写 `http://127.0.0.1:8001`。
4. 基础地址后面不要加 `/app`。具体分析路径由接入程序添加。
5. 保存，按第 6 步交付的停止/启动方式重启接入程序，让配置生效。

以上地址用于本机进程；如果后来改为容器运行，必须按容器网络重新配置，不能直接照抄 localhost。

**完成标志：**接入程序使用的后端地址与第 11 步验证的地址一致。

## 第 13 步：在单聊里发一段英文

**由你操作，这一步是真实模型链路测试。**

1. 打开与机器人的单聊。
2. 粘贴 `The patient has SOB and CP.` 并发送一次。
3. 等待“已收到/处理中”提示及最终回复；不要连续重复发送。
4. 检查结果是否包含扩写文本、各项映射及状态。
5. 确认 WITHHELD 等状态没有被写成“全部成功”。示例是否获得编码，以实际返回为准。

**完成标志：**从飞书输入，到现有后端处理，再返回同一单聊，完整走通一次。

如果只有“处理中”：记录时间和任务编号，让 Codex 检查后端请求与投递状态。不要立刻重复提交，因为请求超时后后端可能仍在运行。

## 第 14 步：把机器人加入一个内部测试群

**由你操作飞书客户端。**

1. 使用一个内部测试群，成员只包含准备参与测试的人。
2. 进入群设置，找到“机器人”或“群机器人”。
3. 点击“添加机器人”，搜索已经发布的 `医学文本标准化助手` 应用机器人。
4. 选择它并添加。不要在此新建 Webhook 自定义机器人。
5. 按第 6 步交付的方法取得该测试群身份，并加入接入程序的允许群列表；必要时重启程序。

**完成标志：**该应用机器人已在群里，接入程序也允许处理这个群。

搜索不到时检查应用是否发布、可用范围以及你是否有加机器人权限；先用同组织内部群测试，外部群能力不在当前验收范围。

## 第 15 步：验证群聊真的只在 @ 时工作

**由你在测试群操作。**

按这个顺序测试：

1. 普通发送 `帮助`，不要 @。机器人应保持安静。
2. 输入 `@`，从弹出的成员/机器人列表选择 `医学文本标准化助手`，再输入 `帮助` 并发送。机器人应回复帮助。
3. 再真正 @ 机器人，后面粘贴 `The patient has SOB and CP.` 并发送一次。
4. 等待结果，确认回复仍在这个群并关联你的消息。

**注意：**手动打出文字“@医学文本标准化助手”不一定是真正的 @，要从飞书候选列表中选中机器人。

**完成标志：**无 @ 不触发，有 @ 能处理，结果不发到别的群或个人聊天。结果在群内对成员可见，因此仍使用虚构文本测试。

## 第 16 步：记录完成情况，然后再考虑服务器

完成下面清单后，才算本机首次接入成功：

- [ ] 单聊帮助能回复。
- [ ] 单聊英文能调用后端并返回结果。
- [ ] 群聊不 @ 时不触发。
- [ ] 群聊真正 @ 时能返回结果。
- [ ] 失败或暂不编码的项目没有被隐藏。
- [ ] 不支持的文件/图片能得到正确提示，不启动分析。
- [ ] 知道程序在哪运行、配置在哪里以及如何停止。
- [ ] Codex 完成去重、并发、重启恢复等工程检查并记录真实测试范围。

随后可以发送：

```text
我已完成操作指南第 16 步。请整理本机验收记录，区分已验证和未验证场景，再根据实测资源与使用频率比较继续用本机和迁移服务器。先不购买或部署服务器。
```

本机电脑关机、休眠、网络断开，或接入程序停止时，机器人就不能正常提供服务。需要长期在线时，再根据实际模型与向量库资源占用选择服务器。

## 日常打开与关闭

开发完成后，让 Codex 将实际启动命令写入接入程序 README，并在桌面或项目目录提供清晰的启动说明。日常顺序固定为：

1. 启动原项目所需依赖和后端。
2. 确认后端可用。
3. 启动飞书接入程序。
4. 发一次帮助检查聊天链路，再开始使用。

停止时使用交付的正常停止方式。程序在前台终端运行时通常使用 `Ctrl+C`，但应先完成或记录正在处理的任务。不要把删除 Docker 容器、删除数据卷或清空数据库当作关闭程序的方法。

## 卡住时，怎样向 Codex 说明

直接使用下面格式，能减少来回确认：

```text
我做到第 __ 步。
我操作的是：__。
预期应该看到：__。
实际看到的是：__。
请先定位这一步，不要跳到后续部署。
```

可以附上不含 App Secret、API Key 和真实病例的截图。只说“没有反应”不容易区分后台权限、连接程序、后端或回复接口哪个环节出问题。
